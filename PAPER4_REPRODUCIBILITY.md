# Reproducing NestyNet Paper IV

Paper IV uses the differential-equation path contained in this NestyNet-SR
repository. The source code is therefore not duplicated in the Paper IV data
deposit. Instead, the separately archived artifact contains the exact benchmark
inputs, the 308-body daily HORIZONS corpus, the validated 308-entry
analytic-surrogate acceleration cache with measured certificates, compact
reference results, and the two final figure PDFs. The software Git revision is
recorded in the artifact.

The permanent Zenodo DOI, archive size, and archive SHA-256 will be entered in
`reproducibility/paper4/archive_record.json` after the final reruns and upload.
Until then, every utility also accepts a locally built archive explicitly.

## Install the software

Use Python 3.10 or newer. Install NestyNet first, then NestyNet-SR and the Paper
IV astronomy dependency:

```bash
cd /path/to/NestyNet
python -m pip install -e .
cd /path/to/NestyNet_SR
python -m pip install -e .
python -m pip install -r reproducibility/paper4/requirements-paper4.txt
```

The final artifact records the exact installed versions used for the published
rerun. The version floors for the shared software are declared in
`pyproject.toml`.

## Inspect the frozen protocol

The protocol is data, not a collection of mutable shell defaults:

```bash
python scripts/run_paper4_reproduction.py --list
python scripts/run_paper4_reproduction.py \
    --workspace ../NestyNet_paper4_recreation/runs \
    --data-root ../NestyNet_paper4_recreation/data \
    --all
```

The second command only prints the fully resolved commands. Add `--run` when
ready to execute them. A machine-readable run manifest records the commands,
Git revision, dirty-tree state, environment and return codes. Groups may be run separately with
`--group benchmarks`, `--group compositional`, `--group symmetry`,
`--group maxwell`, or `--group kepler`. Use `--smoke` for wiring checks only;
smoke outcomes are not paper results. Steps without a declared bounded smoke
recipe are skipped instead of accidentally launching their full computation.

Important protocol choices are explicit:

- scalar STLSQ and hybrid runs share the same six trajectories per problem;
- the complex suite pins `--engine sparse --sparse_library class`;
- the compositional suite is limited to cases 900--903;
- the exact Maxwell and surrogate-noise experiments are separate steps;
- the Kepler analysis uses all 308 Sun-centred HORIZONS trajectories from
  1980-01-01 through 2009-12-31 at one-day cadence.

For the initial final rerun, before a Paper IV artifact exists, point the
runner at the source checkout's exact inputs explicitly:

```bash
python scripts/run_paper4_reproduction.py \
    --workspace ../NestyNet_paper4_recreation/runs \
    --data-root data \
    --kepler-manifest examples/kepler_ephemeris_real/data/raw_states_manifest_jpl_ssodnet_mass_gt_1e17_arc15000_1d.json \
    --kepler-selection examples/kepler_ephemeris_real/data/selection_jpl_ssodnet_mass_gt_1e17_arc15000_summary.json \
    --kepler-cache examples/kepler_ephemeris_real/data/surrogate_accels_1d \
    --all --jobs 1 --run
```

After publication, the setup utility supplies localized archived paths, so the
two Kepler overrides are no longer needed.

## Create a recreation directory

After the Zenodo record is finalized, this downloads and verifies it:

```bash
python scripts/setup_paper4_reproduction.py ../NestyNet_paper4_recreation
```

Before publication, use a local artifact:

```bash
python scripts/setup_paper4_reproduction.py \
    ../NestyNet_paper4_recreation \
    --archive /path/to/NestyNet_paper4_artifacts.tgz
```

The resulting directory keeps immutable reference material separate from new
runs:

```text
NestyNet_paper4_recreation/
├── NestyNet_SR -> source checkout
├── data/                  # links to verified exact inputs
├── reference/             # immutable extracted Zenodo artifact
├── results_ref -> reference/results_ref
├── figures_ref -> reference/figures
├── runs/                  # new experiment outputs
└── paper4_reproduction_manifest.json
```

The setup utility verifies every archived file against `SHA256SUMS`, rejects
unsafe tar members, and creates a localized Kepler manifest without modifying
the archived reference copy.

## Sealed-test scoring

The benchmark marks reported in the paper are sealed-test marks. After the
scalar arms have run, score every case's final equation on two fresh
trajectories (ic6, ic7), generated by extending the protocol's seeded
initial-condition stream; the script verifies that ic0--ic5 are reproduced
byte-identically before using the two new draws:

```bash
python3 scripts/score_paper4_sealed_test.py --results-root <runs>/results
python3 scripts/score_paper4_sealed_test_complex.py --results-root <runs>/results
```

Outputs land in `<runs>/results/sealed_test/<arm>/summary.json` (validation
and sealed statuses per case, status counts) and are validated against
`expected_results.sealed_test` in `protocol.json`; the regenerated
trajectories go to `<runs>/results/sealed_test_data/` and are not shipped.

## Build the final Zenodo artifact

Run the full protocol into a clean workspace, inspect the results, then from the
workspace parent run:

```bash
bash make_nestynet_paper4_artifact.sh
```

The wrapper accepts environment overrides such as `PAPER4_WORKSPACE`,
`PAPER4_DATA_ROOT`, `PAPER4_RESULTS_ROOT`, `PAPER4_KEPLER_DATA_ROOT`,
`PAPER4_OUTPUT_DIR`, and `PAPER4_ARCHIVE`.

Strict mode refuses to build unless it finds the manuscript totals:

- scalar STLSQ: 57 cases, 40 PASS / 9 PARTIAL / 8 FAIL;
- scalar hybrid: 57 cases, 53 PASS / 4 PARTIAL / 0 FAIL;
- complex class-library STLSQ: 26 cases, 23 PASS / 3 PARTIAL / 0 FAIL;
- compositional cases 900--903: four PASS results.

It additionally requires the exact unique benchmark IDs and published
per-problem statuses, all six scalar and
compositional trajectories per case, both real components for every complex
case, every Maxwell input bundle, and one required compact result from every
reported experiment. The 308 Kepler rows must have unique orbit/HORIZONS IDs,
the documented Sun-centred 1980--2009 daily metadata, 10,958 rows per body, and
matching physical CSV row counts. The Maxwell and Kepler publication figures
must also have been regenerated into the clean result workspace. The full
non-smoke run manifest must cover every protocol step with zero return codes and must match the clean Git revision
used to build the archive. Commit the final code before the definitive rerun;
strict publication builds reject a dirty source checkout.

The Kepler cache is validated as a one-to-one 308-file inventory against the
ephemeris manifest. Every entry must provide `ax`, `ay`, `input_sha`, and
`provenance_json`, have the full 10,958-row acceleration arrays, and carry the
measured position-to-velocity derivative certificate quoted in the paper.

Only the final JSON/CSV summaries, human-readable equations, reports and PDFs
are copied from the result directories. Checkpoints, logs, exploratory result
trees, alternative Kepler cadences and local absolute paths are excluded. The
two top-level figure PDFs are taken from the regenerated clean result
workspace, not from a possibly stale manuscript directory. The builder emits
both the `.tgz` archive and a record template containing its byte
size and SHA-256; copy those values into
`reproducibility/paper4/archive_record.json` after the Zenodo upload.

During setup, `SHA256SUMS` must cover every regular artifact file exactly once;
unlisted extras, duplicate checksum rows, archive links, path traversal and
non-canonical/duplicate tar names are rejected.
